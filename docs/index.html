El manifiesto es la fuente de verdad.

El código, la infraestructura, las pruebas y los diagramas son proyecciones. axon verify falla en CI cuando dejan de coincidir. 

curl -fsSL https://raw.githubusercontent.com/Andrew-Tellez/axon/main/install.sh | sh

El problema

Preguntá en cualquier equipo con veinte microservicios: ¿quién consume este evento y qué se rompe si le cambio un campo?

La respuesta honesta es «hay que leer cinco repos». Los frameworks actuales no ayudan porque viven dentro de un lenguaje (NestJS, Spring, Micronaut) o son un runtime que hay que desplegar y operar (Dapr). Ninguno sabe que el order.placed@v1 que emite un servicio en Go es el mismo que consume un servicio en Kotlin. Esa relación existe solo en la cabeza del equipo, hasta que alguien renuncia.

La idea. El manifiesto es diseño de alto nivel —límites de servicio, topología, qué garantiza cada uno. El compilador lo baja a diseño de bajo nivel: nivel de aislamiento, política de reintentos, firmas de método, recursos de infraestructura. Y verifica que sigan de acuerdo. 
                     ┌─ axon build      código: contratos, clase base, clientes resilientes
  asyncapi.yaml ─────┤                     (axon import)
                     ├─ axon test       testkit: contrato, idempotencia, máquinas
                     ├─ axon openapi    OpenAPI 3.1 de toda la plataforma
manifiesto.toml ─────┼─ axon infra      IaC: local · gcp · aws · k8s
                     ├─ axon rls        RLS por fila y vistas enmascaradas
   fuente de verdad  ├─ axon ci         pipeline: gates de axon, deploy del target
                     ├─ axon graph      topología de eventos
                     ├─ axon classes    diagrama de clases
                     ├─ axon er         entidad-relación (de las migraciones)
                     ├─ axon states     máquinas de estado del dominio
                     ├─ axon seq        flujo causal esperado
                     ├─ axon trace      flujo causal REAL (debug local)
                     ├─ axon discover   registro de servicios y métodos
                     └─ axon verify     drift: falla en CI

Instalar

Un binario. Sin Node, sin Python, sin JVM. Corre igual en tu laptop y en un contenedor de CI vacío.

# macOS y Linux, arm64 y x86_64
curl -fsSL https://raw.githubusercontent.com/Andrew-Tellez/axon/main/install.sh | sh

# o desde el código
cargo install --git https://github.com/Andrew-Tellez/axon

El instalador acepta AXON_INSTALL_DIR y AXON_VERSION.

El manifiesto

Un archivo TOML por servicio. Todo lo demás se deriva de acá.

service = "payments"
version = "1.2.0"
owner   = "equipo-pagos"   # gobernanza: nada sin dueño
tier    = "0"              # criticidad: decide SLO y alertas
pii     = ["customer_email"] # se redacta en logs, se enmascara en la base

[emits."payment.captured@v1"]     # dominio.hecho@versión, siempre
paymentId = "uuid"
amount    = "money"            # un float para dinero es un bug esperando su turno

[consumes."order.placed@v1"]
handler = "onOrderPlaced"

[methods.capturePayment]
http       = "POST /v1/payments"
auth       = "required"        # obligatorio: el edge falla cerrado
idempotent = true               # obligatorio si muta
timeout_ms = 8000
in  = { orderId = "uuid", amount = "money" }
out = { paymentId = "uuid" }

[[depends]]
service    = "orders"
method     = "getOrder"
timeout_ms = 1000              # obligatorio: sin presupuesto, no hay llamada
retries    = 3                 # solo si el otro método es idempotente
breaker    = true

[patterns]
outbox = true                  # bus.publish desaparece del código generado

[cap]
consistency  = "strong"       # el dinero no admite un saldo viejo
on_partition = "reject"       # antes de servir algo viejo, no sirve nada

[machine.payment]
initial = "pending"
final   = ["refunded", "failed"]

[machine.payment.transitions.capture]
from  = ["pending"]
to    = "captured"
on    = "capturePayment"
emits = "payment.captured@v1"

[infra]
state         = "postgres"
migrations    = "sql/payments/"
tenant_column = "tenant_id"    # toda tabla la necesita; axon rls la aplica
secrets       = ["STRIPE_API_KEY"]

[infra.buckets.assets]
public    = true               # público ⇒ CDN, y sin él no lo es
cache_ttl = 86400

[env.prod]                        # los entornos son deltas, no copias
min_instances = 3

Tipos: string int float bool timestamp uuid json money. Todo campo es obligatorio — no hay opcionales, así que agregar uno a una versión publicada rompe igual que quitarlo.

Comandos

Todos escriben a stdout y ninguno toca el disco. <fuentes> son directorios, archivos .toml o URLs de servicios vivos.

ComandoQué produce
axon build <m> <fuentes>Contratos tipados, envelope, clase base, dispatch() idempotente, tabla de transiciones y clientes resilientes.
axon test <m> <fuentes>Testkit autocontenido: dobles en memoria, fixtures del esquema del emisor y dos suites exportadas.
axon openapi <fuentes>OpenAPI 3.1 con Idempotency-Key obligatorio y errores RFC 7807.
axon infra <fuentes>Plan neutral renderizado a local, gcp, aws, k8s o plan (JSON).
axon rls <fuentes>Políticas RLS por fila y vistas enmascaradas por columna, como una migración más.
axon ci <m>Pipeline: los gates los sabe axon, el deploy sale del --target.
axon baseline <fuentes>Snapshot de los contratos publicados. Se regenera al publicar.
axon import asyncapi <f>AsyncAPI 2.x o 3.x → manifiesto. Entrar sin reescribir nada.
axon discover <fuentes>Registro de servicios y métodos, de disco y de servicios corriendo.
axon trace [log]La cadena causal real, desde el causationId de los envelopes.
axon verify <fuentes>Todas las reglas. Sale con 1 si hay errores.

Patrones: declarados, no recordados

Un patrón que hay que acordarse de aplicar no es un patrón: es una convención que alguien va a romper a las 3am. Acá se declara y el compilador lo emite.

PatrónSe declaraQué produce
Transactional outbox[patterns] outboxLos emisores escriben en el outbox; bus.publish desaparece del código.
Consumidor idempotentesiempredispatch() deduplica por id de envelope antes de rutear.
Cadena causalsiempretraceparent + correlationId + causationId, propagados por el emisor.
Dead lettersiempreDLQ en los cuatro targets. No hay forma de declarar un consumidor sin ella.
Database per service[infra] stateUna base por servicio, y verify bloquea toda FK que cruce el límite.
Circuit breaker[[depends]]Cliente con timeout, backoff con jitter y circuito medio abierto.
Idempotency-KeyidempotentHeader obligatorio en el OpenAPI y en toda llamada reintentable.
Expand / contractnombre del archivoUn DROP fuera de un .contract.sql es un error.
State pattern[machine.*]Tabla exhaustiva y tipada; una transición ilegal revienta.
Los patrones GoF viven un nivel abajo, en el código que escribe el equipo — para eso está gof-patterns, en seis lenguajes. axon se ocupa de los arquitectónicos: los que cruzan procesos y que ninguna librería dentro de un lenguaje puede garantizar sola.

El lado del teorema CAP que sí se elige

La tolerancia a particiones no es una opción: la red se parte. Lo que se elige es qué hacer mientras está partida, y esa decisión cambia el código.

strong / reject (CP)eventual / degrade (AP)
AislamientoSERIALIZABLEREAD COMMITTED
Obsolescencia—max_staleness_ms, obligatoria
Firma del cliente(input, e)(input, e, respaldo)

La última fila es la que importa: si declarás degrade, el cliente generado exige un parámetro respaldo. No podés decir «elijo disponibilidad» y después no escribir qué se sirve cuando el otro lado no está. No es una convención — no compila.

Verificación de drift

Lo que convierte al manifiesto en algo más que documentación.

$ axon verify manifests/
error: billing consume payment.refunded@v1 pero nadie lo emite
error: payments.payment.stuck no es final y no tiene salida; es un deadlock
error: orders.payment.order_id -> payment: FK cruza el limite de servicio
error: order.placed@v1.total: cambio de `money` a `int` en una version publicada;
       publica `order.placed@v2` en su lugar
warn: payments es `strong` y llama a orders que es `eventual`: la garantia de
      la ruta es la del mas debil, no la tuya

Contratos

Evento consumido que nadie emite. Dos emisores con esquemas distintos. Un método que el otro servicio no expone.

Versiones publicadas

Contra axon.baseline.json: un campo que cambia, aparece o desaparece; un evento que cambia de dueño; una ruta que se mueve.

Resiliencia

Dependencia sin timeout_ms. Reintentos sobre un método no idempotente. Reintentos sin breaker.

Datos

FK que cruza el límite de un servicio. Tabla sin la columna del inquilino. Migración destructiva sin .contract.sql.

Máquinas de estado

Estados inalcanzables, deadlocks, disparadores fantasma y compensaciones rotas.

Gobernanza

Servicio sin dueño o sin criticidad. Prefijos de dominio fuera del catálogo. Demasiadas dependencias síncronas.

Una versión publicada es inmutable. Si de verdad querés retirar una, la quitás del axon.baseline.json en el mismo PR: ese diff es la vía de escape, y se revisa como cualquier otro cambio. No hay --force que se pueda copiar sin pensar.

Seguridad

Cada regla cita su categoría del OWASP Top 10 (2021), porque un error que no dice por qué importa se silencia con un allow.

Regla
A01Ruta pública que muta en un servicio tier = "0"error
A01Tabla sin la columna del inquilino cuando hay tenant_columnerror
A02Un secreto literal donde va su nombreerror
A04Ruta pública sin timeout_mserror
A05Bucket público sin retention_daysaviso
A08[ci].image sin digest — una etiqueta es mutableaviso
A09Un campo pii devuelto por una ruta públicaerror

Y lo que no se avisa, se genera endurecido:

A05 · el pod

runAsNonRoot, readOnlyRootFilesystem, drop ALL, seccompProfile, sin token de service account, y una NetworkPolicy de denegación por defecto.

A01 · el ingreso

Un servicio sin ninguna ruta pública se despliega con ingreso interno: no tiene puerta a internet aunque alguien se equivoque en el gateway.

A08 · el deploy

El pipeline construye, toma el digest y despliega por digest, con provenance.

A09 · los logs

axon build emite camposPII y un redactar() recursivo. Un dato personal se filtra por un log, no por un exploit.

RLS y enmascarado

axon rls cruza dos cosas que axon ya sabe —el esquema real, leído de las migraciones con un parser SQL, y los campos pii— y emite una migración más: 

ALTER TABLE "order" ENABLE ROW LEVEL SECURITY;
ALTER TABLE "order" FORCE ROW LEVEL SECURITY;   -- también al dueño de la tabla
CREATE POLICY "order_inquilino" ON "order"
  USING ("tenant_id" = current_setting('axon.tenant', true)::uuid)
  WITH CHECK ("tenant_id" = current_setting('axon.tenant', true)::uuid);

CREATE OR REPLACE VIEW "order_enmascarada" AS SELECT
  id, total_cents, status, '[redactado]'::text AS "customer_email"
FROM "order";
REVOKE ALL ON "order" FROM axon_lectura;
La regla que importa es la de verify: una tabla que se olvida de la columna del inquilino no recibe política, y una tabla sin política no falla — devuelve las filas de todos. Ese es el modo de fallo silencioso que la declaración elimina.

Local no es un subsistema aparte

Es otro target del mismo plan. Por eso local y producción no pueden divergir.

$ axon infra manifests/ --target local > axon.local.yml
$ docker compose -f axon.local.yml up -d --wait
# broker, Postgres por servicio, migraciones aplicadas, MinIO, el edge y tus servicios

$ curl -X POST localhost:8080/v1/orders -d '{...}'
$ axon trace .axon/local.ndjson
flujo fce36b59-36c7-4d88-81d1-25d90988e204
└─ POST /v1/orders <- http
   └─ order.placed@v1 <- orders
      └─ payment.captured@v1 <- payments

axon seq --events da el flujo esperado; axon trace --seq da el real. Diferenciarlos es un diff, y es la prueba de extremo a extremo que corre en CI del propio repo.

Plugins

Un plugin es cualquier ejecutable en el PATH llamado axon-*. Recibe JSON por stdin, escribe por stdout. Sin ABI, sin cargar librerías, sin versiones que casen: el modelo de git y de protoc.

ClaseSe invoca conRecibeDevuelve
axon-gen-<lang>axon build --lang go{manifest, peers}código fuente
axon-infra-<target>axon infra --target pulumiel plan neutralIaC
axon-check-<regla>axon verify (todos, siempre)todos los manifiestos[{level, message}]

Una regla de gobernanza propia, completa:

#!/bin/sh
# axon-check-nombres — ningún servicio se llama "service" o "api"
jq -c '[.[] | select(.service|test("^(service|api)$"))
        | {level:"error", message:("\(.service): nombre genérico prohibido")}]'
$ axon verify manifests/
error: [axon-check-nombres] api: nombre generico prohibido

Bloquea el pipeline exactamente igual que una regla nativa. axon-gen-go es el generador de referencia — escrito en Go, no importa nada de axon, y produce Go idiomático: interfaz de handlers en vez de herencia, ctx primero, OrderID y no OrderId.

Estado

Preview. La superficie de comandos es estable; el formato del manifiesto todavía puede cambiar antes de v1.

Los generadores no se validan con asserts propios: se validan con la herramienta real de su ecosistema. Un compilador que solo se verifica a sí mismo produce salida inválida —lo comprobé, los tres primeros la producían.

Lo que se generaCómo se comprueba
El TypeScripttsc --strict --noEmit
El Gogo vet
El Terraformterraform validate con providers reales, sin advertencias
El testkitnode --test contra el servicio de ejemplo real
La RLSse aplica a un Postgres real y se comprueba que aísla
El sistema completo./demo.sh: levanta, dispara un flujo y diffea la traza contra el manifiesto

Saltado a propósito

Un generador nativo (TS) y el resto por plugin. Un solo modelo de ejecución (container) y un solo dialecto SQL (PostgreSQL). Sin runtime propio: Bus, Inbox y Outbox son interfaces de una línea. Y verify compara declaraciones, todavía no el cloud desplegado.
